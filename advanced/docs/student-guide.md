# 四次实验：从跑通到独立分析

建议已学习 Python 基础、NumPy 数组、最小二乘和均方根。尚未学习深度学习也可以完成前三次实验。

## 实验一：认识数据和时间边界

先完成 README 的 CPU 运行步骤，打开 `data_audit.json`、`excluded_windows.json` 和两张图。报告写明预测量、单位、采样、输入长度、输出长度和有效窗口数。

阅读 `load_clock` 与 `make_windows`，回答：

- C/D 是两颗什么卫星，是否对应北斗 PRN Cxx？
- 第一条预测为什么是起报时刻之后 10 秒？
- 为什么 2160 个等间隔样本的首末跨度不是整 6 小时？
- D 星少了哪个起报窗口？为什么不直接补齐？
- 日期标签为什么不能直接标成 UTC？

交付：一张数据流程图、一张缺口说明表、一份原始运行结果。不要修改参考数据和图。

## 实验二：理解多项式预报

设最后历史时刻为 0，历史横坐标为负，未来横坐标为正。先在历史上估计参数：

$$\hat b(t)=a_0+a_1t \quad\text{或}\quad \hat b(t)=a_0+a_1t+a_2t^2.$$

使用小时作为拟合横坐标、ns 作为相对钟差。`prepare_history` 先以最后观测为零点，因此末值锚定相当于从多项式预测中减去拟合截距。注意“线性回归”本身也是从历史数据学习参数。

先比较已有的 10 min、1 h、6 h 基线，解释为什么更长历史或更高次数不保证更好的外推。然后在自己的分支添加一个固定的 30 min 线性基线，保持所有起报点不变，并给方法设置独立名称。

交付：每颗星四个提前量的结果、两张误差曲线、对模型偏差与短时变化的解释。不能只保留最好的方法或窗口。

## 实验三：独立计算误差

对一个起报点的 H 个未来点，定义：

$$e_i=(\hat b_i-b_i)\times 10^9,\qquad RMSE=\sqrt{\frac1H\sum_{i=1}^H e_i^2},\qquad MAE=\frac1H\sum_{i=1}^H|e_i|.$$

其中 b 的单位为秒，e 的单位为 ns。终点误差是 e_H；它与整个区间的 RMSE 不是同一个量。

用 `predictions.csv` 自己计算一个窗口，再计算同星、同方法的总体值。总体 pooled RMSE 是把相应区间的全部误差点合起来求 RMSE。本实验各窗口等长，因此等于各窗口 RMSE 平方的平均再开方；不等于直接平均窗口 RMSE。

运行 `verify_results.py` 与自己的计算交叉核验。不要用可能接近零、跨零或具有任意参考偏置的钟差计算 MAPE 来评价本实验。

交付：自己的误差计算程序及与导出结果的差异。再尝试把输入先转为 float32 后相减，观察精度损失；提交改动前后对比，不把这一错误版本合入主实验。

## 实验四：TimesFM 或新的独立测试日期

有条件时按 README 增加 TimesFM，保持同一数据、历史长度、起报点、评价指标。比较直接输入与外部去趋势：它们改善是否在两颗星上都一致？q10–q90 的实测覆盖率是否接近名义 80%？

学习模型的运行不等于理解全部架构。先定位 `contexts` 数组、预测调用和单位恢复；验证任何未来真值都没有传入预测函数，再阅读 Transformer 或尝试 Darts 中的小模型。

进一步研究时，使用更长日期范围，先按时间锁定训练、验证、测试目标区间，再构造窗口；训练标签不能跨入验证/测试期。测试期前的历史可作为实际可用上下文。标准化、去趋势、超参数选择都必须遵守可用时间边界。测试日期只能用于最终评价，不能反复挑窗口追求更低误差。

交付：模型配置、代码提交号、数据来源和哈希、完整指标、失败窗口、跨日误差以及至少一个负面结果。多窗口可能相关，不能把高度重叠窗口当成独立样本做显著性检验。
